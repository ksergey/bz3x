# doip/ — UDS over DoIP для Toyota bZ3X

`doip.py` — консольная утилита: VIN, язык обоих дисплеев, инженерное меню,
включение ADB. Работает по ISO 13400 (DoIP) поверх TCP — CAN-шина не трогается,
адаптер ELM327 не нужен. Только Python 3 stdlib.

**Роли адресов:** тестер `--source` (по умолчанию `0x0722` для языковых команд,
`0x0001` для остальных), ГУ `--target` (`0x0E80` / `0x0DFF`). Выбор
автоматический по команде, переопределяется ключами.

---

## 1. Настройка DoIP-подключения в Linux

iwd тут не участвует — он только для Wi-Fi. Для проводного адаптера
(Ethernet из OBD) достаточно `ip` из iproute2 (`ifconfig` — устаревший
net-tools, лучше не использовать).

```bash
# 1) найти имя интерфейса адаптера
ip -o link show
#    появится новая запись, напр. enp3s0 (или usb0, если это USB-dongle)

# 2) поднять и назначить адрес
ip link set dev enp3s0 up
ip addr add dev enp3s0 10.1.0.1/24

# 3) проверить линк (должно быть state UP и, в идеале, LOWER_UP)
ip addr show dev enp3s0
```

Проверка, что сеть до машины живая:

```bash
ping -c 3 10.1.0.79      # если ГУ не отвечает на ICMP — не страшно
nc -vz 10.1.0.79 13400   # главная проверка: должно быть "succeeded!"
ip neigh show dev enp3s0 # должен появиться MAC 10.1.0.79 — значит L2 есть
```

Откат после работы:

```bash
ip addr del dev enp3s0 10.1.0.1/24
ip link set dev enp3s0 down
```

Грабли:

- **`state DOWN` / `NO-CARRIER`** — нет линка. Либо не та пара пинов в OBD
  (распиновка Ethernet в разъёме bZ3X не подтверждена — у разных maker'ов DoIP
  сидит на разных пинах), либо адаптеру не хватает питания.
- **Конфликт маршрутов**: если в системе уже есть сеть 10.1.0.x — проверь,
  куда реально уходят пакеты: `ip route get 10.1.0.79`.
- **DHCP в бортсети нет** — всем раздаётся статика руками, поэтому нужен п.2.
- Если адаптер **Wi-Fi-донгл** (сам раздаёт точку) — подключись через
  `iwctl station wlan0 connect <SSID>` и смотри, какой адрес он выдаёт
  (DHCP обычно есть, `--host` будет IP самого донгла).

Резервный путь без адаптера — adb-туннель (нужен тот же комп с adb):

```bash
adb shell pm disable-user --user 0 com.gxa.firewall   # открыть DoIP на ГУ
adb forward tcp:13400 tcp:13400
./doip.py vin                                         # host 127.0.0.1 — по умолчанию
# в конце:
adb forward --remove tcp:13400
adb shell pm enable com.gxa.firewall
```

## 2. Что делает doip.py

| Команда | Действие | Безопасность |
|---|---|---|
| `./doip.py vin` | VIN головного устройства (`22 F190`) | ✅ read-only |
| `./doip.py lang` | язык **главного** дисплея (DID `0x0110`) и **малого** (`0x0101`) | ✅ read-only |
| `./doip.py en` | главный дисплей → английский (DID `0x0110`=1) | ⚠️ **ЗАПИСЬ** |
| `./doip.py cn` | главный дисплей → китайский (`0x0110`=0) | ⚠️ **ЗАПИСЬ** |
| `./doip.py set N` | главный дисплей: произвольный байт | ⚠️ **ЗАПИСЬ** |
| `./doip.py cluster_on` | малый дисплей → английский (DID `0x0101`, бит `0x02`) | ⚠️ **ЗАПИСЬ** |
| `./doip.py cluster_off` | малый дисплей → китайский | ⚠️ **ЗАПИСЬ** |
| `./doip.py uds 22F189 22F186` | произвольные UDS-запросы после unlock | зависит от запроса |
| `./doip.py menu` | открыть инженерное меню ГУ (`31 01 2B00`) | ⚠️ **ЗАПИСЬ** |
| `./doip.py adb` | включить ADB на ГУ (`31 01 AE65 01`) | ⚠️ **ЗАПИСЬ** |
| `./doip.py discover` | UDP-broadcast поиск DoIP-узлов | ✅ read-only |

Общие ключи: `--host` (по умолчанию `127.0.0.1` = adb forward; для адаптера
`--host 10.1.0.79`), `--offset` (байт-язык в DID кластера, по умолчанию `0x29`),
`-q` (без дампа TX/RX), `--timeout`, `--source`, `--target`, `--version`.

Каждая команда записи до отправки печатает текущее значение (это готовый
откат), потом записывает и перечитывает результат.

## 3. Что безопасно, а что нет

✅ **Безопасно в любой момент (read-only):** `vin`, `lang`, `discover`,
`uds` с запросами чтения (`22 ...`).

⚠️ **Записи в ГУ** (`en`, `cn`, `set`, `cluster_on/off`, `menu`, `adb`,
`uds` с `2E`/`31`): перед этим

- машина стоит, **в «P»**, зажигание ACC/ON;
- на ходу ничего не отправлять;
- другие программы диагностики/телематики закрыты;
- есть запасной вариант отката (см. ниже).

## 4. Что стоит запомнить

1. **Запись начинается с чтения.** Первая команда на машине — всегда `lang`
   (или `vin`). Она печатает текущие байты — сохрани вывод в файл:
   `./doip.py --host 10.1.0.79 lang | tee /tmp/lang_before.txt`.
2. **Откат.**
   - Главный дисплей: `./doip.py cn` (или `set <старый байт>`).
   - Кластер: скрипт печатает строку вида
     `откат: ./doip.py uds 2E0101<старый байт>` — держи её под рукой.
3. **Сессия/безопасность не вечно живые.** SecurityAccess действует до
   закрытия подключения; каждая команда скрипта открывает своё соединение и
   свой unlock — ничего вручную делать не надо.
4. **Cooldown после неудач.** Если поймал NRC `0x36`/`0x37` (превышены
   попытки / таймаут) — выключи зажигание, подожди пару минут, повтори. Не
   «долби» запросы подряд.
5. **Кеш HMI.** После переключения DID главный экран может сменить язык не
   сразу — помогает перезапуск HMI или цикл зажигания.
6. **Байт-язык кластера** находится на offset `0x29` в записи DID `0x0101`
   (по разбору HMI-прошивки). Если `cluster_on` написал OK, а приборка не
   сменилась — сравни `lang` до/после штатной смены (если она доступна) и
   подбери `--offset 0x2A/0x2B/0x2C`.
7. **Русский язык** в HMI есть (styleId 3 из SYSettingHmi), но через
   DID `0x0110` переключаются только `0` (CN) и `1` (EN) — русский ставится
   только штатным меню HMI, если оно разблокировано.
8. **Файрвол.** При адаптерном пути (вариант с ODB-Ethernet) — ничего не
   трогаем. При adb-пути гасим/возвращаем `com.gxa.firewall` парой команд
   из п.1 — не забудь вернуть `pm enable` в конце.
9. Машина не пострадает от **чтения**, но **запись** DID/команд — это
   запись в диагностику головного блока: думай перед тем, как вводить, и не
   запускай записи «на посмотреть».

## 5. Проблемы и диагностика

- `DoIP: routing activation отклонена` — тестер-адрес не принят. Попробуй
  `--source 0x0001` (или наоборот `0x0722`).
- `UDS 7F xx NN` — NRC расшифровка в `NRC`-таблице в `doip.py`
  (`0x22`=conditionsNotCorrect — машина не в том режиме; `0x36/0x37` —
  cooldown; `0x31` — DID не поддерживается).
- `соединение закрыто` — редко, но ГУ рвёт TCP при чужом/поддельном типе
  сообщения; проверь `--version` (0x02/0x03).
- `узлов не найдено` в `discover` — ГУ отвечает только на точечный доступ
  через adb forward, это не ошибка.

Прошивки, на которых проверялось статически: F2 (S202_250707), F3 (S214_251031).
На живой машине до конца не прогнано — начни с `lang`, пришли вывод, если
что-то пойдёт не так.
