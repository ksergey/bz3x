# bZ3X — команды ELM/STN адаптера (из bz3x-tool 1.2.4)

Команды восстановлены из бинаря `bz3x-tool 1.2.4`. Это ровно те строки, что тул шлёт в
ELM327 / STN (vLinker FS) адаптер. Адрес ГУ: запрос `0x72B`, ответ `0x7AB`, 11-бит.

> Отличие от 1.0.9: ручной Flow Control (`ATFCSH/ATFCSD/ATFCSM`) убран — теперь включается
> **`ATCAF1`** (CAN Auto Formatting), и адаптер сам собирает многокадровые ISO-TP ответы.

---

## Как тул строит команды (форматные строки из бинаря)

| Строка в бинаре | Значение |
|---|---|
| `ATE0` `ATL0` `ATS1` `ATH1` | эхо выкл, без LF, пробелы вкл, заголовки вкл |
| `ATSP6` / `ATSP8` / `ATSPB` | выбор протокола: ISO 15765 11/500 · 11/250 · user-B |
| `ATSH %03X` | заголовок запроса (напр. `ATSH 72B`) |
| `ATCRA %03X` | фильтр приёма (напр. `ATCRA 7AB`) |
| `ATCM 000` | маска CAN (при пассивном прослушивании) |
| `ATCAF1` | авто-ISO-TP (сборка многокадровых ответов) |
| `ATST64` | таймаут ответа = 0x64 |
| `ATAT1` | адаптивное ожидание = 1 |
| `STP %02X` (напр. `STP53`) | STN: выбор протокола пресетом |
| `STPO %02X` | STN: открыть протокол N |
| `STPBR %d` | STN: задать скорость шины |
| `ATMA` | пассивно слушать шину |
| `ATI` / `ATZ` | идентификация / сброс адаптера |

---

## 1. Идентификация адаптера

```
ATZ
ATI
```

Ожидается ответ с `ELM` / `STN` / `OBD` в строке.

---

## 2. Инициализация ELM327 (HS-CAN, авто-ISO-TP)

```
ATE0
ATL0
ATS1
ATH1
ATSP6
ATCAF1
ATST64
ATAT1
ATSH 72B
ATCRA 7AB
```

- `ATSP6` — ISO 15765-4, 11-бит, 500 кбит/с. Если не отвечает, тул пробует `ATSP8`, затем `ATSPB`.
- `ATSH 72B` / `ATCRA 7AB` — адреса ГУ bZ3X.
- `ATCAF1` — включает авто-сборку ISO-TP, поэтому отдельный Flow Control не задаётся.

### Вариант для STN / vLinker FS (цифровое переключение)

```
ATE0
ATL0
ATS1
ATH1
STP53
STPBR 500000
ATCAF1
ATST64
ATSH 72B
ATCRA 7AB
```

## 3. Пассивная диагностика шины (ATMA — ничего не передаёт)

Именно эту последовательность тул использует для «слушаю шину 1.5 с»:

```
ATE0
ATL0
ATS1
ATH0
STPO <NN>        (STN: открыть протокол NN, напр. STPO33 для HS-CAN)
ATH1
ATMA             (монитор всех кадров; стоп — любой символ)
```

Печатает `шина живая: N кадров, ID: …` или `NO DATA` / `тихо`.

---

## 4. UDS-обмен (разблокировка) — отправляется как hex-кадры

После инициализации (п.2) тул шлёт UDS-сервисы по шагам. С `ATCAF1` в адаптер уходят
только байты сервиса (ISO-TP собирается автоматически):

```
10 03            [1] расширенная диагностическая сессия        -> 50 03
27 01            [2] запрос seed (SecurityAccess, уровень 01)   -> 67 01 <seed>
27 02 <KEY>      [3] отправка ключа (seed->key, AES)            -> 67 02
31 01 2B00       [4] открыть инженерное меню (RoutineControl)   -> 71 01 2B00
   либо
31 01 AE65 01    [4] включить USB ADB                           -> 71 01 AE65 00
10 01            [5] вернуть обычную сессию                     -> 50 01
22 F1 86         [5] прочитать активную сессию (проверка)       -> 62 F1 86 …
```

Доп. (read-only):

```
22 F1 90         прочитать VIN                                  -> 62 F1 90 <VIN>
```

Примечания из логики тула:
- если `seed` нулевой (`67 01 00000000`) — доступ уже открыт, шаг `27 02` пропускается;
- на `27 01` ГУ может ответить `7F 27 78` (responsePending) или `7F 27 7F` — значит, ещё
  вычисляет seed: **повторяйте `27 01`** с шагом ~300 мс, держа сессию (`3E 00` раз в ~2 с),
  пока не придёт `67 01 <seed>`. Бросать сессию не нужно — это штатная пауза, а не отказ;
  на клоне ELM327 «зависший» ожидание такого ответа может вылезти строкой `STOPPED`;
- перед рутиной возможен шаг со шлюзом: `set-pin на узле 0x0501` (ack шлюза);
- отрицательный ответ: `7F <SID> <NRC>` (напр. `7F 27 35` = invalidKey, `7F 31 31` = requestOutOfRange).

## 5. Проверка, что протокол встал (STN)

```
STPR             номер текущего протокола
STPBRR           текущая скорость шины
```

## Готовые блоки для копипаста в терминал

**ELM327, открыть инженерное меню (ручной ввод ключа):**

```
ATZ
ATI
ATE0
ATL0
ATS1
ATH1
ATSP6
ATCAF1
ATST64
ATAT1
ATSH 72B
ATCRA 7AB
10 03
27 01
2702<KEY>
31 01 2B00
10 01
22 F1 86
```

**То же, но включить ADB вместо меню:** замените `31 01 2B00` на `31 01 AE65 01`
(ожидаемый ответ `71 01 AE65 00`).

> `<KEY>` — 4 байта, вычисленные из seed по алгоритму seed→key (AES-128; ключ в 1.2.4 не менялся
> относительно 1.0.9). Нулевой seed = доступ уже открыт, ключ слать не нужно.
