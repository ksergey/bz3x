# bz3x_lang.py — смена языка Toyota bZ3X по UDS/DoIP

Скрипт переключает язык обоих дисплеев головного устройства (AVNT) через
диагностический канал DoIP (ISO 13400) — тот же путь, что у дилерского стенда.
Зависит только от соседнего `doip.py` (чистый Python 3, без внешних библиотек).

## DID головного устройства

| DID (LE на проводе) | Что хранит | Значения |
|---|---|---|
| `0x0110` (`10 01`) | язык главного дисплея (Android HMI) | `0`=китайский, `1`=английский |
| `0x0101` (`01 01`) | конфигурация кластера (QNX, малый дисплей), ~0x2C+ байт | бит `0x02` байта-языка: установлен=английский, снят=китайский |

Полный реестр языков HMI (styleId, из классов `Language$Xxx` в SYSettingHmi):
`0=Chinese 1=English 2=Arabic 3=Russian 4=ChineseHK 5=German 6=French 7=Italian
8=Spanish 9=Holland 10=Norway 11=Sweden 12=Portugal 13=Vietnam 14=Thai
15=Indonesia 16=Malay 17=Latin 18=Brazil 19=Unknown`.
Через DID `0x0110` переключаются только `0`/`1`.

## Подготовка

1. **Сеть до ГУ.** Два варианта:
   - **adb**: `adb forward tcp:13400 tcp:13400` — тогда запускать с `--host 127.0.0.1` (по умолчанию).
     Перед этим открыть DoIP на бортовой сети (см. ниже) — иначе файрвол ГУ режет диагностику:
     ```bash
     adb shell pm disable-user --user 0 com.gxa.firewall
     ```
     (обратно: `pm enable com.gxa.firewall`)
   - **DoIP-адаптер в OBD** (Ethernet): `--host 10.1.0.79`. Самый чистый вариант —
     adb и файрвол вообще не затрагиваются.
2. Зажигание в ACC/ON, автомобиль в «P», на ходу ничего не отправлять.
3. `read` всегда первая — она безопасна и фиксирует текущие значения для отката.

## Команды

| Команда | Действие | Запись? |
|---|---|---|
| `./bz3x_lang.py read` | прочитать оба DID, объяснить значения | нет |
| `./bz3x_lang.py en` | главный дисплей → английский | да |
| `./bz3x_lang.py cn` | главный дисплей → китайский | да |
| `./bz3x_lang.py set N` | главный дисплей: записать байт `N` (напр. `set 1`) | да |
| `./bz3x_lang.py cluster_on` | кластер → английский (поставить бит `0x02`) | да |
| `./bz3x_lang.py cluster_off` | кластер → китайский (снять бит `0x02`) | да |
| `./bz3x_lang.py raw 220101` | произвольный UDS-запрос после unlock | зависит |

Каждая запись: сначала читает и печатает старое значение (это твой откат),
пишет, затем перечитывает и сверяет.

Ключевые параметры: `--host`, `--source 0x0722` (адрес тестера), `--target 0x0E80`
(AVNT), `--offset` (индекс байта-языка в записи DID `0x0101`, по умолчанию `0x29`),
`-q` (без дампа TX/RX).

## Порядок на машине

```bash
# подготовка (вариант adb)
adb shell pm disable-user --user 0 com.gxa.firewall
adb forward tcp:13400 tcp:13400

# фиксируем текущее состояние
./bz3x_lang.py read

# главный дисплей → EN, затем кластер → EN
./bz3x_lang.py en
./bz3x_lang.py cluster_on

# проверка результата на экранах; откат, если что-то не так:
./bz3x_lang.py cn                      # вернуть главный на китайский
./bz3x_lang.py cluster_off             # вернуть кластер

# в конце (вариант adb)
adb shell pm enable com.gxa.firewall
```

## Байтовый уровень (что отправляет скрипт)

Для каждой записи выполняется последовательность:

```
10 02                 — расширенная диагностическая сессия   → 50 02
27 01                 — запрос seed (level 0x01)             → 67 01 <seed4>
27 01 <key4>          — отправка ключа                       → 67 01 (положительный)
22 <DID LE>           — чтение                               → 62 <DID LE> <данные>
2E <DID LE> <байт>    — запись 1 байта                       → 6E <DID LE>
```

`seed2key`: AES-128-ECB (фиксированный ключ) над `seed + level×12`, реализация —
в `doip.py` (`seed2key`, чистый Python).

## Ошибки (NRC)

`doip.py` сам ждёт ответ при NRC `0x78` (pending) и падает с расшифровкой:

| NRC | Значение | Что делать |
|---|---|---|
| `0x12` | subFunctionNotSupported | не та сессия/уровень — попробовать `raw "1003"` и т.п. |
| `0x13` | invalidLength | битый запрос (не должно возникать в готовых командах) |
| `0x22` | conditionsNotCorrect | условия не выполнены — зажигание, режим P, двигатель |
| `0x31` | requestOutOfRange | DID не поддерживается этой прошивкой |
| `0x35` | invalidKey | ошибка в seed→key (не должно возникать) |
| `0x36` | exceedNumberOfAttempts | превышены попытки SecurityAccess — выключить зажигание, подождать, повторить |
| `0x37` | requiredTimeDelayNotExpired | таймаут после неудачных попыток — ждать (обычно минуты) |
| `0x7E/0x7F` | subFunctionNotSupportedIn(Active)Session | сменить сессию |

DoIP-уровень: `diagnostic NACK 0x..` — тестер-адрес не принят; попробуй
`--source 0x0001` (некоторые прошивки принимают только его).

## Тонкости

- **Кластерный байт.** Запись DID `0x0101` — ровно 1 байт (`2E 0101 <b>`), чтение
  возвращает длинную запись. Байт-язык — на offset `0x29` от начала UDS-ответа
  (данные начинаются с индекса 3: `62 01 01 <...>`). Если после `cluster_on`
  приборка не сменилась, но запись принята (OK) — попробуй `--offset 0x2A`,
  `0x2B`, `0x2C` (сравнивая `read` до/после штатной смены, если она доступна).
- **Откат кластера** по значению байта — скрипт печатает его перед записью
  (`raw 2E0101<старый байт>`).
- **Кеш HMI.** После смены DID главный экран может подхватить язык не сразу —
  перезапуск HMI или короткий цикл зажигания.
- Если язык в HMI переключается штатным меню — сделай `read` до и после,
  чтобы сверить свой байт-язык с тем, что пишет штатная логика.

## Ограничения

- Проверено только на прошивках F2 (S202_250707) / F3 (S214_251031) по статике;
  на живом автомобиле до конца не прогнано.
- Пиши только те байты, которые читал; не отключай ничего на ходу.
- Русский язык в HMI существует в прошивке (styleId 3), но через DID `0x0110`
  не переключается — только штатным меню HMI, если оно разблокировано.
