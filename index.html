    ADB · справка и команды (без действий). Выполняются с ПК по USB ADB.
    
      
    
        
    Две фазы
    
        
      
          
    • 1. Включить ADB — по CAN (эта страница умеет): авторизация + рутина
            3101AE6501 (успех 7101AE6500). Включает USB-debugging на ГУ.
            → вкладка «Процедура», кнопка «включить ADB».
      • 
          
    • 2. Команды — по USB ADB с ПК: ноутбук USB-кабелем в порт мультимедиа, дальше
            обычный adb (platform-tools). Браузер ADB-протокол по USB не умеет — только ПК.
      • 
        
    

        
    Русский язык (ru-RU)
    
        
    adb shell app_process … Bz3xVisitHelper locale ru-RU --apply
adb shell getprop persist.sys.locale          # проверка == ru-RU
    
        
    Вызывает системный updatePersistentConfiguration с LocaleList ru-RU.
          Это исключение — идёт на уровне shell, root не нужен.
    

        
    Часовой пояс (напр. Europe/Moscow)
    
        
    adb shell su -c 'setprop persist.sys.timezone Europe/Moscow'
adb shell getprop persist.sys.timezone        # проверка
adb reboot                                    # применится после перезагрузки
    

        
    TTL (напр. 64)
    
        
    adb shell su -c 'echo 64 > /proc/sys/net/ipv4/ip_default_ttl'
adb shell cat /proc/sys/net/ipv4/ip_default_ttl   # проверка
# точечно для раздачи (чтобы до оператора дошло 64):
adb shell su -c 'iptables -t mangle -A POSTROUTING -j TTL --set-ttl 65'
    

        
    ⚠ TTL и часовой пояс требуют root
    
        
    ip_default_ttl, iptables и persist.sys.* пишутся только под root.
          Обычный ADB даёт shell (uid 2000), не root. Проверка:
    
        
    adb shell id                 # uid=2000(shell) → root нет
adb root                     # ошибка = нельзя (серийная сборка)
adb shell 'su -c id'         # есть su? → root доступен
    
        
    Без root TTL/таймзона не меняются. Изменения ip_default_ttl/iptables
          не переживают перезагрузку (нужен boot-скрипт).
    

        
    Перезагрузка
    
        
    adb reboot                                 # обычный, без recovery/bootloader
adb shell getprop sys.boot_completed       # ждёт завершения загрузки
adb wait-for-device                        # возврат ADB

    КАКОЙ РАЗЪЁМ (bZ3X)
    
        
    
          
    Два OBD-разъёма. Рабочий для ГУ — СПРАВА, со стороны
            пассажира (не левый под рулём).
    
          
    3/11  MS-CAN -> ГУ  <= этот
6/14  HS-CAN
4/5   GND
16    +12V
    
          
    На правильном STP53 + 22F190 проходят;
            на неправильном — CAN ERROR.
    
        
    
        
    
        
    
          СТОП при ? / ERROR / NO DATA / CAN ERROR / BUS ERROR / UNABLE TO CONNECT / 7F xx xx.
    
          Версия должна быть 8789CVN020  S.242, иначе ключ не отправлять.
    
          Шина IHU — MS-CAN 125k (STP53, пины OBD 3/11).
    
          seed->key считается на самой странице (keybar в терминале или /key <seed>);
          строка 2702<KEY> подставит текущий ключ.
